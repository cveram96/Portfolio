Project Overview & Architecture

The Northwind database is an industry-standard relational benchmark simulating a global wholesale distributor managing products, inventory, customers, suppliers, and fulfillment. This project moves far beyond introductory queries to demonstrate enterprise-grade SQL engineering, addressing real-world reporting challenges such as join fan-out, discount accounting, revenue momentum, and customer lifecycle cohort modeling.

Entity-Relationship Schema Summary:

  • Customer: Client master data, corporate identities, and geographies.
  • Order & OrderDetail: Header-line transactional structure capturing orders, quantities, unit prices, and discount percentages.
  • Product & Category: Catalog hierarchy, unit costs, inventory stock, and reorder thresholds.
  • Supplier: Vendor supply chain partners, lead times, and fulfillment origin.
  • Employee: Sales organizational hierarchy and territory assignments.
  • Shipper: Logistics logistics carriers and transit dates.

Part 1: Core Commercial Operations (Data Hygiene & Bug-Fixed)

Establishing accurate operational reporting while correcting common SQL traps (such as cartesian duplication and ignoring transaction discounts).

1. Top 5 Products by Net Revenue (Accounting for Discounts)

SELECT 
    p.ProductName,
    c.CategoryName,
    ROUND(SUM(od.UnitPrice * od.Quantity * (1 - od.Discount)), 2) AS NetRevenue,
    SUM(od.Quantity) AS UnitsSold
FROM OrderDetail od
JOIN Product p ON od.ProductId = p.Id
JOIN Category c ON p.CategoryId = c.Id
GROUP BY p.Id
ORDER BY NetRevenue DESC
LIMIT 5;

Business Context: Standard sales reports often calculate gross volume (`UnitPrice * Quantity`). Applying `(1 - od.Discount)` captures the actual realized net cash flow, identifying Côte de Blaye and Thüringer Rostbratwurst as the primary revenue engines.

2. Top Customers & Order Frequency (Preventing Join Fan-Out)

SELECT 
    c.CompanyName,
    c.Country,
    COUNT(DISTINCT o.Id) AS TotalOrders,
    ROUND(SUM(od.UnitPrice * od.Quantity * (1 - od.Discount)), 2) AS TotalSpent,
    ROUND(SUM(od.UnitPrice * od.Quantity * (1 - od.Discount)) / COUNT(DISTINCT o.Id), 2) AS AvgOrderValue
FROM Customer c
JOIN 'Order' o ON c.Id = o.CustomerId
JOIN OrderDetail od ON o.Id = od.OrderId
GROUP BY c.Id
ORDER BY TotalSpent DESC
LIMIT 5;

Data Hygiene Note: Joining `Order` to `OrderDetail` produces multiple line items per order. Using `COUNT(DISTINCT o.Id)` ensures orders are not artificially multiplied by line item counts, preventing inflated transaction metrics.

3. Supplier Fulfillment Lead Time (Logistics Bottlenecks)

SELECT 
    s.CompanyName AS SupplierName,
    s.Country,
    COUNT(DISTINCT o.Id) AS OrdersFulfilled,
    ROUND(AVG(julianday(o.ShippedDate) - julianday(o.OrderDate)), 1) AS AvgFulfillmentDays
FROM 'Order' o
JOIN OrderDetail od ON o.Id = od.OrderId
JOIN Product p ON od.ProductId = p.Id
JOIN Supplier s ON p.SupplierId = s.Id
WHERE o.ShippedDate IS NOT NULL
GROUP BY s.Id
ORDER BY AvgFulfillmentDays DESC
LIMIT 5;

Business Context: Analyzes turnaround latency between purchase placement and carrier handover, flagging potential supply chain delays.

4. Inactive Account Identification (Churn Risk Audit)

SELECT 
    c.CompanyName,
    c.ContactTitle,
    c.Country,
    MAX(o.OrderDate) AS LastOrderDate
FROM Customer c
LEFT JOIN 'Order' o ON c.Id = o.CustomerId
GROUP BY c.Id
HAVING LastOrderDate < date('now', '-1 year') OR LastOrderDate IS NULL
ORDER BY LastOrderDate ASC;

Bug-Fixed Execution: Fixes alias translation mismatches (`LastOrderDate`) to correctly filter dormant accounts that have placed zero orders or have been inactive for over twelve months.

Part 2: Advanced SQL & Window Functions (Analytics Engineering)

Utilizing Common Table Expressions (CTEs) and analytical window functions (`DENSE_RANK`, `LAG`, `SUM() OVER`) to solve complex analytical questions without inefficient correlated subqueries.

5. Top 3 Products within Each Category (Partitioned Ranking)

WITH CategoryProductSales AS (
    SELECT 
        c.CategoryName,
        p.ProductName,
        ROUND(SUM(od.UnitPrice * od.Quantity * (1 - od.Discount)), 2) AS Revenue,
        DENSE_RANK() OVER (
            PARTITION BY c.Id 
            ORDER BY SUM(od.UnitPrice * od.Quantity * (1 - od.Discount)) DESC
        ) AS CategoryRank
    FROM OrderDetail od
    JOIN Product p ON od.ProductId = p.Id
    JOIN Category c ON p.CategoryId = c.Id
    GROUP BY c.Id, p.Id
)
SELECT 
    CategoryName, 
    CategoryRank, 
    ProductName, 
    Revenue
FROM CategoryProductSales
WHERE CategoryRank <= 3
ORDER BY CategoryName, CategoryRank;

Technical Rationale: Rather than running multiple category-specific queries, `DENSE_RANK() OVER (PARTITION BY c.Id)` generates departmental rankings in a single scan, providing localized product leadership insights across Beverages, Dairy, Produce, and Confections.

6. Month-over-Month (MoM) Revenue Growth Rate

WITH MonthlyRevenue AS (
    SELECT 
        strftime('%Y-%m', o.OrderDate) AS OrderMonth,
        ROUND(SUM(od.UnitPrice * od.Quantity * (1 - od.Discount)), 2) AS CurrentMonthRevenue
    FROM 'Order' o
    JOIN OrderDetail od ON o.Id = od.OrderId
    GROUP BY OrderMonth
)
SELECT 
    OrderMonth,
    CurrentMonthRevenue,
    LAG(CurrentMonthRevenue, 1) OVER (ORDER BY OrderMonth) AS PreviousMonthRevenue,
    ROUND(
        (CurrentMonthRevenue - LAG(CurrentMonthRevenue, 1) OVER (ORDER BY OrderMonth)) 
        / LAG(CurrentMonthRevenue, 1) OVER (ORDER BY OrderMonth) * 100, 2
    ) AS MoMGrowthPercent
FROM MonthlyRevenue
ORDER BY OrderMonth;

Technical Rationale: Uses `LAG()` to pull the prior month's aggregate into the current row, calculating exact commercial momentum without self-joins.

7. Year-to-Date (YTD) Running Total Revenue

WITH MonthlyTotals AS (
    SELECT 
        strftime('%Y', o.OrderDate) AS OrderYear,
        strftime('%Y-%m', o.OrderDate) AS OrderMonth,
        ROUND(SUM(od.UnitPrice * od.Quantity * (1 - od.Discount)), 2) AS MonthlySales
    FROM 'Order' o
    JOIN OrderDetail od ON o.Id = od.OrderId
    GROUP BY OrderMonth
)
SELECT 
    OrderYear,
    OrderMonth,
    MonthlySales,
    ROUND(SUM(MonthlySales) OVER (
        PARTITION BY OrderYear 
        ORDER BY OrderMonth
    ), 2) AS YTD_RunningRevenue
FROM MonthlyTotals
ORDER BY OrderMonth;

Technical Rationale: Cumulative window partitioning resets at the turn of each calendar year, tracking progress toward annual revenue benchmarks.

8. Customer Reorder Velocity (Average Days Between Purchases)

WITH OrderSequence AS (
    SELECT 
        CustomerId,
        OrderDate,
        LAG(OrderDate) OVER (
            PARTITION BY CustomerId 
            ORDER BY OrderDate
        ) AS PreviousOrderDate
    FROM 'Order'
),
OrderIntervals AS (
    SELECT 
        CustomerId,
        ROUND(julianday(OrderDate) - julianday(PreviousOrderDate), 1) AS DaysBetweenOrders
    FROM OrderSequence
    WHERE PreviousOrderDate IS NOT NULL
)
SELECT 
    c.CompanyName,
    COUNT(i.DaysBetweenOrders) AS RepeatOrdersCount,
    ROUND(AVG(i.DaysBetweenOrders), 1) AS AvgDaysBetweenOrders
FROM OrderIntervals i
JOIN Customer c ON i.CustomerId = c.Id
GROUP BY c.Id
HAVING RepeatOrdersCount >= 10
ORDER BY AvgDaysBetweenOrders ASC
LIMIT 5;

Technical Rationale: Calculates repurchase frequency at the individual account level, revealing that top accounts such as Save-a-lot Markets reorder every 19 days on average.

Part 3: Strategic Customer Intelligence (RFM & Cohort Retention)

Bridging database querying with managerial marketing strategy: customer tiering and retention cohort analysis coded in 100% pure SQL.

9. Automated RFM Customer Segmentation (Pure SQL)

WITH CustomerAggregates AS (
    SELECT 
        c.Id AS CustomerId,
        c.CompanyName,
        MAX(o.OrderDate) AS LastOrderDate,
        COUNT(DISTINCT o.Id) AS Frequency,
        ROUND(SUM(od.UnitPrice * od.Quantity * (1 - od.Discount)), 2) AS Monetary
    FROM Customer c
    JOIN 'Order' o ON c.Id = o.CustomerId
    JOIN OrderDetail od ON o.Id = od.OrderId
    GROUP BY c.Id
),
RFM_Quartiles AS (
    SELECT 
        CustomerId,
        CompanyName,
        Frequency,
        Monetary,
        LastOrderDate,
        NTILE(4) OVER (ORDER BY LastOrderDate ASC) AS R_Score,
        NTILE(4) OVER (ORDER BY Frequency ASC) AS F_Score,
        NTILE(4) OVER (ORDER BY Monetary ASC) AS M_Score
    FROM CustomerAggregates
)
SELECT 
    CompanyName,
    R_Score, F_Score, M_Score,
    Frequency AS TotalOrders,
    Monetary AS LifetimeSpend,
    CASE 
        WHEN R_Score >= 3 AND F_Score >= 3 AND M_Score >= 3 THEN 'VIP Champion'
        WHEN R_Score >= 3 AND F_Score >= 2 THEN 'Loyal Customer'
        WHEN R_Score = 1 AND F_Score >= 3 THEN 'High-Value At Risk'
        WHEN R_Score = 1 AND F_Score = 1 THEN 'Dormant Account'
        ELSE 'Regular Buyer'
    END AS CustomerSegment
FROM RFM_Quartiles
ORDER BY Monetary DESC
LIMIT 8;

Management Impact: Using `NTILE(4)` categorizes all accounts into actionable marketing quadrants without external statistical packages, pinpointing high-spend accounts requiring immediate account manager retention calls.

10. Customer Retention Cohort Analysis (Pure SQL Matrix)

WITH CustomerFirstOrder AS (
    SELECT 
        CustomerId,
        MIN(OrderDate) AS FirstOrderDate,
        strftime('%Y-%m', MIN(OrderDate)) AS CohortMonth
    FROM 'Order'
    GROUP BY CustomerId
),
UserMonthlyActivity AS (
    SELECT 
        o.CustomerId,
        c.CohortMonth,
        (CAST(strftime('%Y', o.OrderDate) AS INTEGER) - CAST(strftime('%Y', c.FirstOrderDate) AS INTEGER)) * 12 +
        (CAST(strftime('%m', o.OrderDate) AS INTEGER) - CAST(strftime('%m', c.FirstOrderDate) AS INTEGER)) AS MonthIndex
    FROM 'Order' o
    JOIN CustomerFirstOrder c ON o.CustomerId = c.CustomerId
)
SELECT 
    CohortMonth,
    COUNT(DISTINCT CustomerId) AS CohortSize,
    COUNT(DISTINCT CASE WHEN MonthIndex = 1 THEN CustomerId END) AS M1_Repeat,
    COUNT(DISTINCT CASE WHEN MonthIndex = 2 THEN CustomerId END) AS M2_Repeat,
    COUNT(DISTINCT CASE WHEN MonthIndex = 3 THEN CustomerId END) AS M3_Repeat,
    ROUND(COUNT(DISTINCT CASE WHEN MonthIndex = 1 THEN CustomerId END) * 100.0 / COUNT(DISTINCT CustomerId), 1) AS M1_RetentionRate
FROM UserMonthlyActivity
GROUP BY CohortMonth
ORDER BY CohortMonth
LIMIT 6;

Management Impact: Generates a classic SaaS/e-commerce cohort retention table directly in SQL, measuring repeat order stability across customer onboarding cohorts.

Part 4: Database Performance & Query Optimization

In production databases with millions of rows, unindexed queries cause heavy table scans and server I/O bottlenecks. We examine execution plans using EXPLAIN QUERY PLAN:

EXPLAIN QUERY PLAN
SELECT c.CompanyName, COUNT(DISTINCT o.Id) AS Orders
FROM Customer c
JOIN 'Order' o ON c.Id = o.CustomerId
GROUP BY c.Id;

Production Optimization Takeaways:

  • Foreign Key Indexing: Ensuring composite indices on `Order(CustomerId, OrderDate)` transforms full-table sequential scans into B-Tree index lookups (`SEARCH TABLE`).
  • Selective Projection: Avoiding `SELECT *` and projecting only required columns reduces memory footprint during hash aggregation (`TEMP B-TREE FOR GROUP BY`).
  • Safe Aggregations: Using `COUNT(DISTINCT)` whenever child detail tables are joined protects against relational duplication.
